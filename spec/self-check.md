# Platform self-check

The library's bit-exact outputs rest on the platform as well as on the operations the
spec pages pin: IEEE-754 binary64 with no contraction into fused multiply-adds, gradual
underflow, and no extended precision or range ([README](README.md#determinism-contract)).
The test suites prove that on the machines they run on. A host that runs the library
somewhere else — Unity's IL2CPP on a phone, Mono, WASM, an unusual NumPy build, a process
that has loaded a library built with `-ffast-math` — runs the self-check inside its real
player or process to learn whether that runtime reproduces the contract.

Python `heaton_life.self_check` (`run()`, `run_all()`, `passed()`, `format_results()`);
C# `SelfCheck` (`Run`, `RunAll`, `Passed`, `Format`, `Names`) and `SelfCheckScope`.

## Contract

- **File-free.** Every input and known answer is embedded. They are generated by
  `python/tools/gen_self_check.py` from the vectors (their output files digested, their
  inputs copied), the spec pages' tables, and exact oracles (`fractions.Fraction`,
  CPython's correctly rounded `float()`), into `python/src/heaton_life/_self_check_data.py`
  and `dotnet/src/HeatonLife.Core/SelfCheckData.cs`. Never edited by hand.
- **Never throws.** A check that throws is a FAIL whose detail is the exception's type and
  message (C#: the inner exception's message when there is one); a passing check's detail
  is `""`.
- **Leaves the orbit cache alone.** Its reference orbits are computed afresh and never
  stored, so a run does not evict a host's cached orbits.
- **Digests** are FNV-1a 64 over explicit little-endian bytes: int32 counts, float64 values
  (every NaN as `0x7FF8000000000000` first where a NaN can occur: table words, the phase
  `t`), RGB bytes.
- **Order.** `fp-contract` runs first, so a report's first FAIL is the root cause, then the
  port's own platform check, then the shared checks below in order.
- **Names are append-only** and never repurposed: a check whose inputs change keeps its
  name only while it witnesses the same faults. The eight names hosts already used —
  `pcg32`, `fma`, `pow10`, `mergelife-upstream`, `mandelbrot-t0`, `center-projection`,
  `grayscott-100`, `reference-orbit` — keep their meaning.

## Scopes and gating

Each check names what its failure invalidates: Simulations, T0 (float64 frames), T1
(perturbation: zooms past 1e12), T2 (floatexp: past 1e290), Color, Movies.
`passed(results, scope)` is true when every check whose scope overlaps ran and passed; a
check missing from the results fails closed, and so does any FAIL for it (results from
several runs may be passed together). `fp-contract` invalidates every float bit-exact
output — every scope, not only deep zoom: contraction changes T0 counts in C# (its
software fma is Dekker's), colors, movie plans and Gray-Scott bits. A host gates on the
tier, not on a literal decade: before rendering any frame whose tier (`fractal.tier_of`,
`FractalEngine.TierOf`) is T1 it asks `passed(results, T1)`, and on a failure clamps to the
last tier that passed.

The render checks' vectors were chosen by fault injection: each has escaping pixels with
varied counts, and each fails when the arithmetic it names is broken (a collapsed
double-double, a dropped `B·δc` term, doubled or zeroed deltas, a Julia rebase onto the
wrong orbit). Some faults change no self-check answer and are left to `fp-contract` (and in
C# `fma`, in Python `numpy-fma`): contraction of the T0 and T1 escape tests, the cardioid
test, T2 landing, the double-double cross terms, Newton's loop, the Burning Ship T1 step,
the reference orbit's escape test on its rounded samples, the depth phase's baseline (every
vector's `cycles_per_octave` is 0 or 0.25, which makes that product exact), and the plain T1
loop's complex multiply when it breaks alone (the BLA loop's shares its arithmetic; only
`mandelbrot-t1-bla` sees a fault in both).

Not included: evolve (about 70 ms per objective; its ingredients are `pcg32`,
`mergelife-upstream` and `fp-contract`).

## Provenance

- Python's suite regenerates both data files in memory and requires them to equal the
  files on disk, so a deliberate vector regeneration that touches a source case fails until
  `gen_self_check.py` is rerun (the parity protocol's first step in `CLAUDE.md`). Inputs
  come from the vectors too — the color frames and options, Gray-Scott's parameters,
  MergeLife's line — so a rerun refreshes inputs and answers together.
- Both suites require `run_all()` / `RunAll()` to pass, and their check names to be
  `fp-contract`, the port's platform check, then the generated shared list — so the ports
  run the same shared checks.
- The C# suite checks the fma answers against the hardware `Math.FusedMultiplyAdd`.

## Cost

Measured on an Apple M-series Mac, single-threaded, in a fresh process: C# about 200 ms
with tiered JIT (about 105 ms with `TieredCompilation=0`; later runs in the same process
40–160 ms), Python about 270 ms. `julia-t2` and `mandelbrot-t1-bla` are most of it. A phone
is several times slower: run it once per process, off the main thread, and keep the results
for gating.
